=encoding utf-8

=head1 NAME

App::Greple::tee - マッチしたテキストを外部コマンドの結果で置き換えるモジュール

=head1 SYNOPSIS

    greple -Mtee command -- ...
    greple -Mtee -E PAT1 command1 -- -Mtee -E PAT2 command2 -- ...

=head1 VERSION

Version 2.00_00

=head1 DESCRIPTION

Greple の B<-Mtee> モジュールは、マッチしたテキスト部分を指定したフィルタコマンドに送り、そのコマンドの結果で置き換えます。アイデアは B<teip> と呼ばれるコマンドに由来します。データの一部だけを外部フィルタコマンドに通すようなイメージです。

フィルタコマンドはモジュール宣言（C<-Mtee>）に続けて記述し、二つのダッシュ（C<-->）で終端します。例えば、次のコマンドはデータ中のマッチした単語に対して、コマンド C<tr> を C<a-z A-Z> の引数で呼び出します。

    greple -Mtee tr a-z A-Z -- '\w+' ...

上記のコマンドは、マッチした単語をすべて小文字から大文字に変換します。実はこの例自体はあまり有用ではありません。というのも、B<greple> 自身が B<--cm> オプションで同様のことをより効率的に行えるからです。

デフォルトでは、コマンドは単一プロセスとして実行され、すべてのマッチしたデータはまとめてそのプロセスに送られます。マッチしたテキストが改行で終わっていなければ、送信前に改行が追加され、受信後に取り除かれます。入力と出力のデータは行単位で対応付けられるため、入力と出力の行数は一致していなければなりません。

B<--discrete> オプションを使うと、マッチした各テキスト領域ごとに個別のコマンドが呼び出されます。違いは次のコマンド群で確認できます。

    greple -Mtee cat -n -- copyright LICENSE
    greple -Mtee cat -n -- copyright LICENSE --discrete

B<--discrete> オプションを用いる場合、入力と出力の行数は一致している必要はありません。

=head1 OPTIONS

=over 7

=item B<--discrete>

マッチした各部分ごとに新しいコマンドを個別に起動します。

=item B<--bulkmode>

B<--discrete> オプションでは、各マッチに対するコマンドはマッチが出力されるときに実行されます。B<--bulkmode> オプションでは、出力前にすべてを一括で実行します。

このオプションは、L</MULTIPLE FILTERS> の新形式では効果がありません。新形式ではフィルターは常にすべてのマッチに対して一度に実行されます。

=item B<--crmode>

このオプションは、各ブロックの途中にあるすべての改行文字をキャリッジリターンに置き換えます。コマンド実行結果に含まれるキャリッジリターンは改行文字に戻されます。これにより、B<--discrete> オプションを使わずとも、複数行から成るブロックをバッチ処理できます。

これは L<ansifold> コマンドの B<--crmode> オプションと相性がよく、CR 区切りのテキストを結合し、CR で区切られた折り畳み行を出力します。

=item B<--fillup>

フィルタコマンドに渡す前に、連続する非空行を1行にまとめます。全角文字（日本語、中国語）の間の改行は削除し、その他の改行は空白に置き換えます。韓国語（ハングル）は ASCII テキスト同様に空白で連結します。

=item B<--squeeze>

連続する2つ以上の改行を1つにまとめます。

=item B<--nofork>

C<&function> で指定した関数を、フォークせずに B<greple> プロセス自身で実行します（L</FUNCTION CALL> を参照）。これがデフォルトです。フォークした子プロセスで実行するには B<--no-nofork> を使用します。このオプションは外部コマンドには影響しません。

=item B<-ML> B<--offload> I<command>

L<teip(1)> の B<--offload> オプションに相当する機能は、別モジュール L<App::Greple::L>（B<-ML>）で提供されています。

    greple -Mtee cat -n -- -ML --offload 'seq 10 20'

B<-ML> モジュールを使って、次のように偶数行のみを処理することもできます。

    greple -Mtee cat -n -- -ML 2::2

=back

=head1 MULTIPLE FILTERS

B<-Mtee> は複数回指定でき、それぞれに独自のパターンとフィルタを指定できます。各フィルタは、それとともに指定されたパターンに適用されます。

    -Mtee [ OPTIONS ] [ COMMAND [ ARGS ... ] ] --

最初の非オプション引数より前はすべてモジュールのオプションであり、残りの C<--> までがコマンドです。たとえば次のコマンドは、C<PAT1> または C<PAT2> に一致する行を B<ansifold> で折り返し、C<PAT3> に一致する行を B<ansicolumn> で表として整形します。

    greple -Mtee --crmode -E PAT1 -E PAT2 '&ansifold' --crmode -w80 -- \
           -Mtee --discrete -E PAT3 '&ansicolumn' -t -- \
           file

形式は2つあります。

=over 4

=item B<Legacy form>

B<-Mtee> 内にパターンがない場合、従来どおり C<--> に続くすべてのパターンにコマンドが適用されます。複数回指定した場合は、最後のものが有効です。

=item B<New form>

B<-Mtee> 内にパターンがある場合、コマンドはその B<-Mtee> 内のパターンにのみ適用されます。

=back

2つの形式を混在させるとエラーになります。C<-Mtee::config(...) -Mtee ...> の前半のように、C<--> より前に何もない B<-Mtee> は設定のみを行い、どちらの形式にも数えられません。

エラーは、出力が行われる前の最初のファイルの検索時に検出されます。

=head2 Options inside -Mtee

=over 4

=item B<--discrete>, B<--bulkmode>, B<--crmode>, B<--fillup>, B<--squeeze>, B<--nofork>

フィルタのモードです。B<--no-crmode> のように、B<--no-> 形式で否定できます。

=item B<-E>, B<--re>

正規表現パターン。

=item B<-e>

パターン。空白を含んでいても1つのパターンとして扱われます。

=item B<--fe>

固定文字列パターン。

=item B<--le>

単一のキーワード、または C<&function>。空白で区切った複数のキーワードを指定するとエラーになります。

=item B<--cm>

そのまま B<greple> に渡されます。色はパターンに結び付けられるのではなく、指定された順にパターン番号へ循環的に割り当てられます（L</LIMITATIONS> を参照）。

=item B<--config>

B<Getopt::EX::Config> が提供するオプションです。B<すべて>のフィルタに共通する設定を変更します。

=back

B<--exclude> などのほかのオプションを指定するとエラーになります。C<--> の後に記述してください。これらはすべてのフィルタに適用されます。

=head2 Priority of modes

モードの値は、実行時に次の順序で決定されます。

=over 4

=item 1.

B<-Mtee> 内で指定したもの（B<--crmode>、B<--no-crmode>）。

=item 2.

C<--> の後、または B<-Mtee::config(...)> で指定したもの。

=back

=head2 Special cases

=over 4

=item *

新形式では、いずれか1つのパターンを含むブロックが処理されるように（OR）、B<--need=1> が自動的に追加されます。これを上書きするには C<--> の後で B<--need> を指定します。B<--need=2> を指定すると AND に戻ります。旧形式は従来どおり（AND）動作します。各 B<-Mtee> および B<-Mtee> を含む各エイリアスオプションが再び B<--need=1> を追加するため、B<--need> はそのすべての後に置いてください。

=item *

コマンドを省略した場合（C<-Mtee -E PAT -->）、パターンはテキストを選択しますが、テキストは変更されません。

=item *

新形式では、B<-Mtee> の外にあるパターンはエラーです。B<-Mtee> の外にある B<--callback> も同様です。

=item *

新形式では、C<--> の後の最初の引数は、パターンとして意図されていても、パターンがすでにオプションで指定されているためパターンとして扱われません。B<greple> はそれをファイル名として扱います。

=item *

異なるフィルタの一致箇所が重なった場合、B<greple> はそれらを1つの領域に結合し、先に開始する一致のフィルタを適用します。

=back

=head2 LIMITATIONS

=over 4

=item *

コマンドラインで B<-Mtee> 内に直接記述した C<{DEFINE}> は展開されません。B<option> 定義内では展開されます。

=item *

B<-M> は引数の先頭になければならないため、B<-Mtee> モジュールの間にほかのオプションを記述することはできません。エイリアスオプションを使用して B<-Mtee> モジュールとほかのオプションを組み合わせます。

=item *

従来どおり、C<--> をコマンド引数に含めることはできません。

=item *

B<--cm> はフィルタごとに独立していません。一部のパターンにだけ指定すると、他の B<-Mtee> 内のものを含む他のパターンの色が、B<greple> の循環割り当てによって変化します。色を指定する際は、すべてのパターンに B<--cm> を指定してください。

=item *

別のモジュールが B<-Mtee> に続く場合（C<-Mtee -E PAT cmd -- -Mcolors>）、パターンはモジュールの B<default> オプションを介して B<greple> に渡され、C<$ENV{NAME}> や C<__PACKAGE__> などのオプション定義の展開がそれらに適用されます。これらをエスケープする処理は行われません。

=item *

B<default> オプションに新形式の B<-Mtee> を含むモジュールが、C<-Mfoo -Mtee -E PAT cmd -- -Mcolors> のように、別のモジュールが続く B<-Mtee> より前に読み込まれると、パターンが失われ、エラー（「passed twice or lost」）として検出されます。モジュールは B<-Mtee> の後に読み込んでください。

=back

=head1 CONFIGURATION

モジュールのパラメータは、次の文法で B<Getopt::EX::Config> モジュールにより設定できます。

    greple -Mtee::config(discrete) ...
    greple -Mtee::config(fillup,crmode) ...

これはシェルのエイリアスやモジュールファイルと組み合わせると便利です。

利用可能なパラメータは次のとおりです: B<discrete>、B<bulkmode>、B<crmode>、B<fillup>、B<squeeze>、B<nofork>。

=head1 FUNCTION CALL

外部コマンドの代わりに、コマンド名の前にC<&>を付けることでPerl関数を呼び出せます。

    greple -Mtee '&App::ansifold::ansifold' -w40 -- ...

関数は次の要件に従う必要があります:

=over 4

=item *

一致したテキストをB<STDIN>から読み込む

=item *

変換結果をB<STDOUT>へ出力する

=item *

引数はC<@ARGV>およびC<@_>の両方で渡される

=back

デフォルトでは、関数はフォークせずにB<greple>プロセス自体で実行されます。したがって、関数によって変更されたグローバル変数の値は次回の呼び出しにも残り、関数内でB<exit>を呼び出すとB<greple>が終了します。B<--no-nofork>オプションを指定すると、関数はフォークされた子プロセスで実行されます。

任意の完全修飾関数名を使用できます:

    greple -Mtee '&Your::Module::function' -- ...

モジュールは未ロードの場合、自動的にロードされます。

便宜のため、以下の短いエイリアスが利用可能です:

=over 4

=item B<&ansicolumn>

C<App::ansicolumn::ansicolumn>を呼び出します。

=item B<&ansifold>

C<App::ansifold::ansifold>を呼び出します。

=item B<&cat-v>

C<App::cat::v-E<gt>new-E<gt>run(@_)>を呼び出します。

=back

関数呼び出しを使用すると、呼び出しごとに外部プロセスを起動するオーバーヘッドを回避でき、B<--discrete>オプションと併用した場合にパフォーマンスを大幅に向上させることができます。

=head1 LEGACIES

B<--blocks> オプションは削除されました。B<greple> に B<--stretch>（B<-S>）オプションが実装されたため、もはや不要です。代わりに次を使用してください。

    greple -Mtee cat -n -- --all -SE foo

=head1 WHY NOT USE TEIP

まず何より、B<teip> コマンドで実現できる場合はそれを使ってください。優れたツールであり、B<greple> よりもはるかに高速です。

B<greple> は文書ファイルの処理を目的に設計されているため、マッチ領域の制御など、それに適した多くの機能を備えています。それらの機能を活用するために B<greple> を使う価値はあります。

また、B<teip> は複数行のデータをひとつの単位として扱えませんが、B<greple> は複数行からなるデータチャンクに対して個別のコマンドを実行できます。

=head1 EXAMPLE

次のコマンドは、Perl モジュールファイル内の L<perlpod(1)> 形式ドキュメントのテキストブロックを見つけます。

    greple --inside '^=(?s:.*?)(^=cut|\z)' --re '^([\w\pP].+\n)+' tee.pm

上記コマンドに B<deepl> コマンドを呼び出す B<-Mtee> モジュールを組み合わせることで、DeepL サービスで翻訳できます。使い方は次のとおりです:

    greple -Mtee deepl text --to JA - -- --fillup ...

ただし、この目的には専用モジュール L<App::Greple::xlate::deepl> のほうが効果的です。実際、B<tee> モジュールの実装のヒントは B<xlate> モジュールから得られました。

=head1 EXAMPLE 2

次のコマンドは、LICENSE ドキュメント内のいくつかのインデントされた部分を見つけます。

    greple --re '^[ ]{2}[a-z][)] .+\n([ ]{5}.+\n)*' -C LICENSE

      a) distribute a Standard Version of the executables and library files,
         together with instructions (in the manual page or equivalent) on where to
         get the Standard Version.

      b) accompany the distribution with the machine-readable source of the Package
         with your modifications.

これらの部分は、B<tee> モジュールと B<ansifold> コマンドを使って再整形できます。両方の B<--crmode> オプションを併用すると、複数行ブロックを効率よく処理できます:

    greple -Mtee ansifold -sw40 --prefix '     ' --crmode -- --crmode --re ...

      a) distribute a Standard Version of
         the executables and library files,
         together with instructions (in the
         manual page or equivalent) on where
         to get the Standard Version.

      b) accompany the distribution with the
         machine-readable source of the
         Package with your modifications.

B<--discrete> オプションも使用できますが、複数のプロセスを起動するため、実行に時間がかかります。

=head1 EXAMPLE 3

ヘッダー行以外の行から文字列を grep したい状況を考えてみます。例えば、C<docker image ls> コマンドの出力から Docker イメージ名を検索したいが、ヘッダー行は残したい場合です。以下のコマンドで実現できます。

    greple -Mtee grep perl -- -ML 2: --discrete --all

オプション C<-ML 2:> は、2行目から最後までを取り出して C<grep perl> コマンドに送ります。行数が変わるため B<--discrete> オプションが必要ですが、コマンドは一度しか実行されないので性能上のデメリットはありません。

同じことを B<teip> コマンドでやろうとすると、C<teip -l 2- -- grep> は出力行数が入力行数より少ないためエラーになります。ただし、得られる結果自体に問題はありません。
