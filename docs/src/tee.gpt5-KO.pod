=encoding utf-8

=head1 NAME

App::Greple::tee - 외부 명령 결과로 일치한 텍스트를 대체하는 모듈

=head1 SYNOPSIS

    greple -Mtee command -- ...
    greple -Mtee -E PAT1 command1 -- -Mtee -E PAT2 command2 -- ...

=head1 VERSION

Version 2.00_00

=head1 DESCRIPTION

Greple의 B<-Mtee> 모듈은 일치한 텍스트 부분을 지정한 필터 명령으로 보내고, 그 결과로 해당 부분을 대체합니다. 이 아이디어는 B<teip>라는 명령에서 유래했습니다. 데이터의 일부만 외부 필터 명령을 통해 전달하는 것과 비슷합니다.

필터 명령은 모듈 선언(C<-Mtee>) 뒤에 오며, 두 개의 대시(C<-->)로 종료합니다. 예를 들어, 다음 명령은 데이터에서 일치한 단어에 대해 C<a-z A-Z> 인자를 사용하여 C<tr> 명령을 호출합니다.

    greple -Mtee tr a-z A-Z -- '\w+' ...

위 명령은 일치한 모든 단어를 소문자에서 대문자로 변환합니다. 사실 이 예시는 B<greple>의 B<--cm> 옵션으로 더 효율적으로 동일 작업을 할 수 있으므로 그다지 유용하지는 않습니다.

기본적으로 명령은 단일 프로세스로 실행되며, 모든 일치 데이터는 함께 섞여 해당 프로세스로 전송됩니다. 일치한 텍스트가 개행 문자로 끝나지 않으면 전송 전 추가하고 수신 후 제거합니다. 입력과 출력 데이터는 줄 단위로 매핑되므로 입력과 출력의 줄 수는 동일해야 합니다.

B<--discrete> 옵션을 사용하면, 각 일치 텍스트 영역마다 개별 명령이 호출됩니다. 다음 명령들을 통해 차이를 확인할 수 있습니다.

    greple -Mtee cat -n -- copyright LICENSE
    greple -Mtee cat -n -- copyright LICENSE --discrete

B<--discrete> 옵션을 사용하면 입력과 출력 데이터의 줄 수가 동일할 필요가 없습니다.

=head1 OPTIONS

=over 7

=item B<--discrete>

일치한 각 부분마다 새 명령을 개별적으로 호출합니다.

=item B<--bulkmode>

B<--discrete> 옵션을 사용하면 각 일치 항목에 대한 명령은 해당 일치 항목이 출력될 때 실행됩니다. B<--bulkmode> 옵션은 출력 전에 모든 명령을 한 번에 실행합니다.

이 옵션은 L</MULTIPLE FILTERS>의 새 형식에서는 효과가 없으며, 이 경우 필터는 항상 모든 일치 항목에 대해 한 번에 실행됩니다.

=item B<--crmode>

이 옵션은 각 블록 중간의 모든 개행 문자를 캐리지 리턴 문자로 바꿉니다. 명령 실행 결과에 포함된 캐리지 리턴은 다시 개행 문자로 변환됩니다. 따라서 B<--discrete> 옵션을 사용하지 않고도 여러 줄로 구성된 블록을 일괄 처리할 수 있습니다.

이는 CR로 구분된 텍스트를 결합하고 CR로 구분된 접힌 줄을 출력하는 L<ansifold> 명령의 B<--crmode> 옵션과 잘 작동합니다.

=item B<--fillup>

필터 명령으로 전달하기 전에 연속된 비어 있지 않은 줄들을 하나의 줄로 결합합니다. 전각 문자(일본어, 중국어) 사이의 개행 문자는 삭제되고, 그 외의 개행 문자는 공백으로 대체됩니다. 한국어(한글)는 ASCII 텍스트처럼 취급되어 공백으로 결합됩니다.

=item B<--squeeze>

연속된 두 개 이상의 개행 문자를 하나로 합칩니다.

=item B<--nofork>

포크하지 않고( L</FUNCTION CALL> 참조) B<greple> 프로세스 자체에서 C<&function>으로 지정한 함수를 실행합니다. 이것이 기본값입니다. 포크된 자식 프로세스에서 실행하려면 B<--no-nofork>를 사용하십시오. 이 옵션은 외부 명령에는 영향을 미치지 않습니다.

=item B<-ML> B<--offload> I<command>

L<teip(1)>의 B<--offload> 옵션에 해당하는 기능은 다른 모듈 L<App::Greple::L> (B<-ML>)에서 제공합니다.

    greple -Mtee cat -n -- -ML --offload 'seq 10 20'

B<-ML> 모듈을 사용하여 다음과 같이 짝수 줄만 처리할 수도 있습니다.

    greple -Mtee cat -n -- -ML 2::2

=back

=head1 MULTIPLE FILTERS

B<-Mtee>를 여러 번 지정할 수 있으며, 각각 자체 패턴과 필터를 가질 수 있습니다. 각 필터는 함께 지정된 패턴에 적용됩니다.

    -Mtee [ OPTIONS ] [ COMMAND [ ARGS ... ] ] --

첫 번째 비옵션 인수 앞의 모든 것은 모듈 옵션이고, 그 뒤부터 C<-->까지는 명령입니다. 예를 들어, 다음 명령은 C<PAT1> 또는 C<PAT2>와 일치하는 줄을 B<ansifold>로 접고, C<PAT3>와 일치하는 줄은 B<ansicolumn>으로 표 형식으로 만듭니다.

    greple -Mtee --crmode -E PAT1 -E PAT2 '&ansifold' --crmode -w80 -- \
           -Mtee --discrete -E PAT3 '&ansicolumn' -t -- \
           file

형식은 두 가지입니다.

=over 4

=item B<Legacy form>

B<-Mtee> 내부에 패턴이 없으면, 이전과 같이 C<--> 뒤에 오는 모든 패턴에 명령이 적용됩니다. 두 번 이상 지정하면 마지막 것이 적용됩니다.

=item B<New form>

B<-Mtee> 내부에 패턴이 있으면, 명령은 해당 B<-Mtee> 안의 패턴에만 적용됩니다.

=back

두 형식을 섞으면 오류입니다. C<-Mtee::config(...) -Mtee ...>의 앞부분처럼 C<--> 앞에 아무것도 없는 B<-Mtee>는 구성만 설정하며 어느 형식에도 해당하지 않습니다.

오류는 출력 전에 첫 번째 파일을 검색할 때 감지됩니다.

=head2 Options inside -Mtee

=over 4

=item B<--discrete>, B<--bulkmode>, B<--crmode>, B<--fillup>, B<--squeeze>, B<--nofork>

필터의 모드입니다. B<--no-crmode>처럼 B<--no-> 형식으로 부정할 수 있습니다.

=item B<-E>, B<--re>

정규 표현식 패턴.

=item B<-e>

패턴입니다. 공백을 포함하더라도 하나의 패턴으로 간주됩니다.

=item B<--fe>

고정 문자열 패턴.

=item B<--le>

단일 키워드 또는 C<&function>입니다. 공백으로 구분된 여러 키워드를 지정하면 오류입니다.

=item B<--cm>

B<greple>에 그대로 전달됩니다. 색상은 패턴에 묶이지 않고 지정된 순서대로 패턴 번호에 순환하여 할당됩니다(L</LIMITATIONS> 참조).

=item B<--config>

B<Getopt::EX::Config>에서 제공하는 옵션입니다. B<모든> 필터에 공통인 설정을 변경합니다.

=back

B<--exclude> 같은 다른 옵션을 지정하면 오류입니다. C<--> 뒤에 작성해야 하며, 모든 필터에 적용됩니다.

=head2 Priority of modes

모드의 값은 실행 시 다음 순서로 결정됩니다.

=over 4

=item 1.

B<-Mtee> 내부에서 지정한 것(B<--crmode>, B<--no-crmode>)입니다.

=item 2.

C<--> 뒤에서 또는 B<-Mtee::config(...)>로 지정한 것입니다.

=back

=head2 Special cases

=over 4

=item *

새 형식에서는 패턴 중 하나라도 포함하는 블록이 처리되도록 B<--need=1>이 자동으로 추가됩니다(OR). 이를 재정의하려면 C<--> 뒤에 B<--need>를 지정하십시오. B<--need=2>는 AND로 되돌립니다. 기존 형식은 이전과 같이 작동합니다(AND). 각 B<-Mtee> 및 B<-Mtee>를 포함하는 각 별칭 옵션은 B<--need=1>을 다시 추가하므로, B<--need>는 모두 뒤에 두십시오.

=item *

명령을 생략하면(C<-Mtee -E PAT -->) 패턴은 텍스트를 선택하지만 텍스트는 변경되지 않습니다.

=item *

새 형식에서는 B<-Mtee> 밖의 패턴은 오류입니다. B<-Mtee> 밖의 B<--callback>도 마찬가지입니다.

=item *

새 형식에서는 옵션으로 이미 패턴이 지정되어 있으므로, C<--> 뒤의 첫 번째 인수는 패턴으로 의도한 경우에도 패턴으로 간주되지 않습니다. B<greple>은 이를 파일 이름으로 간주합니다.

=item *

서로 다른 필터의 일치 영역이 겹치면 B<greple>은 이를 하나의 영역으로 병합하고, 먼저 시작하는 일치 영역의 필터를 적용합니다.

=back

=head2 LIMITATIONS

=over 4

=item *

명령줄에서 B<-Mtee> 내부에 직접 작성한 C<{DEFINE}>은 확장되지 않습니다. B<option> 정의 내부에서는 확장됩니다.

=item *

B<-M>는 인수의 맨 앞에 있어야 하므로 B<-Mtee> 모듈 사이에는 다른 옵션을 작성할 수 없습니다. 별칭 옵션을 사용하여 B<-Mtee> 모듈과 다른 옵션을 결합하십시오.

=item *

이전과 마찬가지로 C<-->는 명령 인수에 포함할 수 없습니다.

=item *

B<--cm>은 각 필터마다 독립적이지 않습니다. 일부 패턴에만 지정하면 다른 B<-Mtee>의 패턴을 포함한 다른 패턴의 색상이 B<greple>의 순환 할당으로 인해 변경됩니다. 색상을 지정할 때는 모든 패턴에 B<--cm>을 지정하십시오.

=item *

다른 모듈이 B<-Mtee> 뒤에 오는 경우(C<-Mtee -E PAT cmd -- -Mcolors>), 패턴은 모듈의 B<default> 옵션을 통해 B<greple>에 전달되며, C<$ENV{NAME}> 및 C<__PACKAGE__>와 같은 옵션 정의의 확장이 해당 패턴에 적용됩니다. 이들은 이스케이프되지 않습니다.

=item *

B<default> 옵션에 새 형식의 B<-Mtee>를 포함하는 모듈이 있다고 가정합니다. C<-Mfoo -Mtee -E PAT cmd -- -Mcolors>처럼 다른 모듈이 뒤따르는 B<-Mtee>보다 먼저 로드되면 패턴이 손실됩니다. 이는 오류("두 번 전달되었거나 손실됨")로 감지됩니다. 이러한 모듈은 B<-Mtee> 뒤에 로드하십시오.

=back

=head1 CONFIGURATION

모듈 매개변수는 다음 구문을 사용하여 B<Getopt::EX::Config> 모듈로 설정할 수 있습니다:

    greple -Mtee::config(discrete) ...
    greple -Mtee::config(fillup,crmode) ...

셸 별칭이나 모듈 파일과 함께 사용하면 유용합니다.

사용 가능한 매개변수: B<discrete>, B<bulkmode>, B<crmode>, B<fillup>, B<squeeze>, B<nofork>.

=head1 FUNCTION CALL

외부 명령 대신, 명령 이름 앞에 C<&>를 붙여 Perl 함수를 호출할 수 있습니다.

    greple -Mtee '&App::ansifold::ansifold' -w40 -- ...

함수는 다음 요구 사항을 따라야 합니다:

=over 4

=item *

일치한 텍스트를 B<STDIN>에서 읽습니다

=item *

변환된 결과를 B<STDOUT>에 출력합니다

=item *

인수는 C<@ARGV>와 C<@_>를 통해 모두 전달됩니다

=back

기본적으로 함수는 포크 없이 B<greple> 프로세스 자체에서 실행됩니다. 따라서 함수가 변경한 전역 변수의 값은 다음 호출에도 유지되며, 함수에서 B<exit>를 호출하면 B<greple>가 종료됩니다. B<--no-nofork> 옵션을 사용하면 함수는 포크된 자식 프로세스에서 실행됩니다.

완전히 한정된 함수 이름이라면 어떤 것이든 사용할 수 있습니다:

    greple -Mtee '&Your::Module::function' -- ...

모듈이 아직 로드되지 않았다면 자동으로 로드됩니다.

편의를 위해 다음의 짧은 별칭을 사용할 수 있습니다:

=over 4

=item B<&ansicolumn>

C<App::ansicolumn::ansicolumn>를 호출합니다.

=item B<&ansifold>

C<App::ansifold::ansifold>를 호출합니다.

=item B<&cat-v>

C<App::cat::v-E<gt>new-E<gt>run(@_)>를 호출합니다.

=back

함수 호출을 사용하면 각 호출마다 외부 프로세스를 시작하는 오버헤드를 피할 수 있으므로, B<--discrete> 옵션과 함께 사용할 때 성능을 크게 향상시킬 수 있습니다.

=head1 LEGACIES

B<--blocks> 옵션이 제거되었습니다. B<greple>에 B<--stretch> (B<-S>) 옵션이 구현됨에 따라 더 이상 필요하지 않습니다. 대신 다음을 사용하십시오.

    greple -Mtee cat -n -- --all -SE foo

=head1 WHY NOT USE TEIP

무엇보다도 B<teip> 명령으로 할 수 있는 일이라면 그렇게 하십시오. 훌륭한 도구이며 B<greple>보다 훨씬 빠릅니다.

B<greple>은 문서 파일 처리를 위해 설계되었기 때문에, 매치 영역 제어와 같은 해당 용도에 적합한 많은 기능을 갖추고 있습니다. 이러한 기능을 활용하기 위해 B<greple>을 사용할 가치가 있을 수 있습니다.

또한 B<teip>은 여러 줄의 데이터를 하나의 단위로 다룰 수 없지만, B<greple>은 여러 줄로 구성된 데이터 청크에 대해 개별 명령을 실행할 수 있습니다.

=head1 EXAMPLE

다음 명령은 Perl 모듈 파일에 포함된 L<perlpod(1)> 스타일 문서의 텍스트 블록을 찾습니다.

    greple --inside '^=(?s:.*?)(^=cut|\z)' --re '^([\w\pP].+\n)+' tee.pm

위 명령에 B<deepl> 명령을 호출하는 B<-Mtee> 모듈을 결합하면 DeepL 서비스로 번역할 수 있습니다. 예시는 다음과 같습니다:

    greple -Mtee deepl text --to JA - -- --fillup ...

전용 모듈 L<App::Greple::xlate::deepl>이 이 목적에 더 효과적입니다. 실제로 B<tee> 모듈 구현의 실마리는 B<xlate> 모듈에서 왔습니다.

=head1 EXAMPLE 2

다음 명령은 LICENSE 문서에서 일부 들여쓴 부분을 찾습니다.

    greple --re '^[ ]{2}[a-z][)] .+\n([ ]{5}.+\n)*' -C LICENSE

      a) distribute a Standard Version of the executables and library files,
         together with instructions (in the manual page or equivalent) on where to
         get the Standard Version.

      b) accompany the distribution with the machine-readable source of the Package
         with your modifications.

이 부분들은 B<tee> 모듈과 B<ansifold> 명령을 사용하여 재포맷할 수 있습니다. 두 B<--crmode> 옵션을 함께 사용하면 여러 줄 블록을 효율적으로 처리할 수 있습니다:

    greple -Mtee ansifold -sw40 --prefix '     ' --crmode -- --crmode --re ...

      a) distribute a Standard Version of
         the executables and library files,
         together with instructions (in the
         manual page or equivalent) on where
         to get the Standard Version.

      b) accompany the distribution with the
         machine-readable source of the
         Package with your modifications.

B<--discrete> 옵션도 사용할 수 있지만, 여러 프로세스를 시작하므로 실행에 더 오래 걸립니다.

=head1 EXAMPLE 3

헤더가 아닌 줄에서 문자열을 grep 하고 싶은 상황을 생각해 보십시오. 예를 들어 C<docker image ls> 명령의 출력에서 Docker 이미지 이름을 검색하되 헤더 줄은 남겨두고 싶을 수 있습니다. 다음 명령으로 할 수 있습니다.

    greple -Mtee grep perl -- -ML 2: --discrete --all

옵션 C<-ML 2:>는 두 번째 줄부터 끝까지를 가져와 C<grep perl> 명령으로 보냅니다. 줄 수가 달라지므로 B<--discrete> 옵션이 필요하지만, 명령이 한 번만 실행되므로 성능 상의 불이익은 없습니다.

같은 작업을 B<teip> 명령으로 시도하면, 출력 줄 수가 입력 줄 수보다 적기 때문에 C<teip -l 2- -- grep>은 오류를 발생시키지만, 출력 자체는 정확합니다.
